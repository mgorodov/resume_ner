# Улучшение базового решения Resume NER

## Исходное состояние (baseline)

- **Модель:** `spacy.blank("en")` — пустая модель SpaCy без предобученных эмбеддингов
- **Архитектура:** `HashEmbedCNN` (width=96, depth=4, embed_size=2000) + `TransitionBasedParser`
- **Данные:** 220 резюме из датасета Dataturks, 11 типов сущностей, train/test split 90/10
- **Обучение:** 10 эпох, dropout=0.2, batch size=1 (по одному примеру), без early stopping
- **Предобученные вектора:** отсутствуют (`pretrained_vectors = null`)

### Проблемы исходного решения

1. **Баг с entity offsets** — при парсинге аннотаций использовался `re.finditer` и бралось первое вхождение текста. Если "Oracle" упоминается 15 раз в одном резюме, все аннотации указывали на первое вхождение, а не на правильное
2. **Массовая потеря данных** — сотни перекрывающихся сущностей просто удалялись
3. **Мусорный класс UNKNOWN** — засорял модель при обучении
4. **Нет аугментации** — 220 резюме критически мало для NER
5. **Обучение по одному примеру** — нестабильное и медленное
6. **Нет early stopping** — фиксированное число эпох без контроля переобучения
7. **Нет per-entity метрик** — непонятно, какие сущности модель ловит, а какие нет

---

## Что было сделано

### 1. Работа с данными

#### Очистка данных (`data_utils.py`)
- **Исправлен баг entity offsets:** используются оригинальные `start`/`end` из аннотации как primary source, с fallback на regex только при несовпадении
- **Улучшена обработка overlapping entities:** при пересечении выбирается более длинный span (стратегия `keep_longer`) вместо слепого удаления второго
- **Удалён класс UNKNOWN** — 2 сущности, которые только мешали
- **Валидация spans** — проверка что `text[start:end]` непустой и в пределах текста
- **Фильтрация пустых резюме** — резюме без аннотаций убраны из обучения

#### Аугментация данных
Три стратегии увеличения обучающей выборки (179 → 716 примеров, **4x**):

| Метод | Описание |
|---|---|
| **Entity Swap** | Замена имён, городов, компаний на случайные из пула (внутри датасета + внешний словарь) |
| **Case Variation** | Случайное изменение регистра: UPPER / lower / Title для каждой сущности |
| **Skill Synonym** | Замена IT-навыков на синонимы по словарю (Java→Kotlin, AWS→Azure, React→Angular, ...) |

#### Новые признаки (Entity Ruler)
Regex-паттерны для структурированных сущностей:
- **Email Address:** `\S+@\S+\.\S+`
- **Graduation Year:** числа 1980–2030
- **Years of Experience:** `N year(s) of experience`, `N+ yrs`

### 2. Более сложные модели и архитектуры

| Модель | Архитектура | Описание |
|---|---|---|
| **A: Baseline** | blank SpaCy + HashEmbedCNN | Пустая модель, учится с нуля на наших данных |
| **B: Pretrained** | en_core_web_lg tok2vec + NER | GloVe вектора (300d, 685k слов) как начальные эмбеддинги |
| **C: Hybrid** | en_core_web_lg + Entity Ruler + NER | Комбинация правил (regex) для Email/Year/Experience + ML для остального |
| **D: Transformer** | roberta-base + NER | Трансформер-модель через spacy-transformers |

#### Улучшения обучения (для всех моделей)
- **Minibatch training** через `spacy.util.minibatch` (compounding 4→32) вместо поштучного обновления
- **Early stopping** по entity-F1 на dev-выборке (patience=5)
- **Train/Dev/Test split:** 179 / 19 / 22 резюме (вместо прямого train/test)
- **Dropout 0.3** (увеличен с 0.2)
- **30 эпох** с early stopping вместо фиксированных 10

## Выводы

1. **Лучшая модель — B+aug (pretrained GloVe + аугментация):** Entity-F1 = 0.6137, что на **+11.7%** выше baseline. Сочетание предобученных векторов и увеличенных данных даёт наибольший эффект.

2. **Аугментация данных — главный фактор улучшения.** При всего 179 резюме в обучающей выборке увеличение до 716 через entity swap, case variation и skill synonym replacement — самый эффективный приём. Средний прирост от аугментации: +0.04 Entity-F1.

3. **Pretrained vectors (GloVe) умеренно помогают сами по себе** (+0.0132 на чистых данных), но **значительно усиливаются аугментацией** (+0.0644). Модель с предобученными эмбеддингами лучше обобщает на аугментированных данных.

4. **Entity Ruler (правила) полезен для структурированных сущностей.** Regex-паттерны для Email, Year, Experience дают +3% F1. Правила надёжно ловят то, что легко формализуется.

5. **Transformer (roberta-base) показывает сопоставимый результат** (F1=0.5949) с Hybrid-моделью (F1=0.5933), но **в 13 раз медленнее** (2610s vs 193s). На 179 примерах трансформер не успевает полностью раскрыть свой потенциал — для него нужно больше данных.

6. **Лучше всего распознаётся Name** (F1=0.96) — имена чётко выделяются в начале резюме. **Хуже всего — Years of Experience** (F1=0.00, всего 4 примера в тесте) и **Graduation Year** (F1=0.37) — малое количество примеров + вариативность формата.

7. **Очистка данных — необходимый фундамент.** Исправление бага с offsets, удаление UNKNOWN, улучшенная обработка overlaps — без этого дальнейшие улучшения невозможны.

8. **Рекомендация для production:** модель B+aug (en_core_web_lg + аугментация) — лучшее соотношение качества и скорости. Для дальнейшего улучшения стоит рассмотреть: увеличение датасета, fine-tune BERT на больших данных, добавление контекстных признаков (секции резюме, форматирование).

## Как запустить

```bash
# Активировать окружение
source venv/bin/activate

# Установить зависимости (если ещё не установлены)
pip install spacy-transformers transformers torch
python -m spacy download en_core_web_lg

# Полный запуск (все 6 экспериментов, ~45 мин с трансформером)
python improved_train_and_evaluate.py

# Быстрый запуск (без трансформера, ~25 мин)
python improved_train_and_evaluate.py --skip-transformer
```
